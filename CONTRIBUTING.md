# Cómo escribimos en este proyecto

La documentación tiene que sonar a alguien que conoce la gestión de cartera y explica su trabajo con naturalidad. Preferimos contar primero qué decisión enfrenta el negocio y luego cómo se estudió. Podemos escribir en primera persona cuando tenga sentido, sin convertir cada párrafo en un discurso de marca.

Usamos prosa y listas cortas cuando ayudan. No hacemos tablas Markdown para ordenar ideas narrativas. Las frases pueden ser breves o largas según lo que haya que explicar; evitamos series de puntos con la misma estructura y muletillas como «En resumen» o «Es importante destacar».

No usamos emojis, guiones largos, puntos suspensivos ni líneas decorativas repetidas. La negrita queda para casos excepcionales, nunca para destacar una frase completa o todas las líneas de una lista. Los títulos deben poder entenderse desde el negocio; los nombres técnicos se explican dentro del texto.

La edición de estilo no autoriza a cambiar una cifra, una fórmula, un enlace, una definición de target, una limitación ni un resultado. Tampoco se suavizan las advertencias para que el modelo parezca mejor. Antes de publicar conviene comparar esos elementos con la versión anterior.

Cuando volvamos a editar este repo, leemos primero este archivo. Si cambia el método o el código, eso se trata como una tarea aparte de la redacción.
